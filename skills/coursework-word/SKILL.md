# Курсовая в Word

## Порядок работы

1. Определить режим: написать раздел, отредактировать содержание, оформить документ или проверить работу. Выполнить заказанный объём; не писать всю курсовую по просьбе подготовить один пункт.
2. Прочитать [оформление](references/formatting.md) и [источники и расхождения](references/sources.md). Для содержания прочитать [структуру](references/structure.md), для главы 2 — [ТЗ](references/technical-specification.md), для титульника и испытаний — [образцы](references/templates.md). Для персонализации использовать [поля проекта](references/project.md) и сведения текущего пользователя. Исходные методички, шаблоны и шрифты включены в `sources/`; пути перечислены в sources.md и разрешаются относительно папки скилла.
3. Сверить сведения с текущими файлами и сообщениями пользователя. При новых редакциях методичек обновить конкретные требования. Не изменять файлы sources/, работать с копиями.
4. Проверить факты, нужные для раздела: процессы, роли, функции, сущности, технологии, результаты испытаний. Сначала использовать доступные код, БД и документы. Спрашивать только существенное недостающее, продолжать независимую работу. Не подменять неизвестное выдуманными фактами; предположения явно обозначать в черновике.
5. При работе с .docx загрузить доступный навык documents и соблюдать его процесс создания, рендера и визуальной проверки. Если он недоступен, использовать эквивалентные средства создания DOCX и просмотра отрендеренных страниц; при невозможности рендера явно сообщить ограничение. Данный скилл задаёт требования колледжа; не заменять их типовым оформлением.
6. Создать или изменить документ, выполнить [проверки](references/checklist.md). Сохранить по действующим правилам среды и дать ссылку на редактируемый .docx. Не подменять его PDF без запроса.

## Приоритеты

Применять текущие явные указания пользователя, затем согласованные требования преподавателя, затем прямые требования методички. Использовать отдельные шаблоны для их конкретной задачи, примеры — для формы, туториалы — только для подтверждённого стека. Расхождения отмечать; продолжать с явно названным рабочим вариантом, если они не мешают задаче. Не спрашивать разрешения для каждого обычного выбора оформления.

Не выдавать выписки из методички за независимо проверенные действующие редакции ГОСТ. При запросе нормативной проверки обращаться к официальным первоисточникам.

## Текст и достоверность

- По согласованному требованию пользователя для тире использовать «–» (U+2013), не использовать длинное тире U+2014. Дефис «-» сохранять внутри слов, например «что-то». Подробности и проверка описаны в formatting.md и checklist.md.

- Писать ясно, предметно, в учебном стиле без воды и повторов. Не использовать «таким образом» и «в настоящее время» в авторском тексте; не искажать точные цитаты и названия.
- Сохранять единые названия ролей, процессов, таблиц, полей и функций в тексте, моделях, SQL и программе.
- Различать требования ТЗ, фактически реализованное поведение главы 5 и инструкции по существующему интерфейсу главы 6.
- Не выдумывать организацию, As-Is, интервью, показатели экономии, апробацию и результаты испытаний. Не отмечать тест «Прошёл» на основании ожидаемого результата.
- Не придумывать источники, ISBN, URL, даты обращения, версии ПО, аппаратные характеристики и сроки восстановления. Проверять по реальным данным.
- Не переносить чужие ФИО, группу, тему «Библиотека», даты, пароли и удачные результаты из примеров. Не включать секреты из строк подключения в записку.
- Не изменять логику пользовательского кода ради удобства описания без соответствующего запроса.

## Выдача

Проверить структуру, ссылки, подписи, оглавление и соответствие реальной работе. После рендера осмотреть все страницы изменённого документа. Исправить обрезку, нечитаемые схемы, случайные пустые страницы, заголовки и подписи, отделённые от объектов. Не утверждать, что визуальная проверка пройдена, если рендер недоступен; назвать конкретное ограничение.

Кратко указать, что подготовлено и какие существенные данные ещё не подтверждены. Не добавлять служебные замечания о противоречиях методички в текст самой курсовой.

## Версия и обновления

Версия и контрольные суммы поставки находятся в [version.json](version.json). Перед первым применением скилла в текущем чате запустить включённую [проверку версии](scripts/check_version.py): `python "<папка скилла>/scripts/check_version.py"`. Проверка только читает файлы и публичный каталог GitHub. Если Python или сеть недоступны, продолжать основную задачу и не утверждать, что актуальность подтверждена. При доступном обновлении кратко сообщить версии и дать пользователю кликабельную ссылку на [актуальный выпуск](https://github.com/NXR333/codex-skills/releases/latest); при локальных изменениях сохранить их. Не заменять файлы автоматически: обновлять по запросу пользователя средствами репозитория. Эта проверка сопоставляет версии поставки и целостность файлов; актуальность содержания методичек устанавливать отдельно по новым материалам и применимым источникам.
