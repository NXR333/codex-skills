# Проверка DOCX и границы автоматизации

[validate_docx.py](../scripts/validate_docx.py) только читает документ. Python 3.10+, сторонние библиотеки не нужны. Он не исправляет файл, не запускает Word и не доказывает пригодность к сдаче.

```text
python scripts/validate_docx.py "Записка.docx" --full
python scripts/validate_docx.py "Раздел.docx"
python scripts/validate_docx.py "assets/coursework-template.docx" --full --allow-placeholders
python scripts/validate_docx.py "Записка.docx" --full --json
python -B -m unittest discover -s scripts -p "test_*.py"
```

Без `--full` проверяется фрагмент: поля PAGE и TOC не требуются. В полной записке `--full` проверяет их наличие, но не актуальность значений. `--allow-placeholders` подавляет предупреждения о квадратных скобках в шаблоне или черновике; он не делает их допустимыми в готовой работе. Без этого флага совпадение с `[текстом]` требует просмотра: это может быть ссылка на источник, а не заполнитель.

Коды возврата: 0 — нет ошибок (предупреждения могут оставаться), 1 — найдены ошибки, 2 — файл не удалось прочитать. Каждое предупреждение нужно разобрать перед выдачей. Не обещать «всё проверено» по нулевому коду.

## Покрытие

| Проверка | Что делает скрипт | Что остаётся вручную |
| --- | --- | --- |
| Страницы | А4 в обеих ориентациях, поля разделов, явный перезапуск номеров | Реальное число страниц, низ/центр номера, отсутствие номера на титульнике, непрерывность и правила подсчёта |
| Основной текст | Унаследованные свойства стилей и прямое форматирование: выравнивание, отступ, интервал, размер | Визуальная плотность, смысловые абзацы, переносы |
| Шрифт и цвет | Явная гарнитура и цвет, предупреждение при неразрешённых свойствах темы | Подмена шрифтов системой, оформление текста в изображениях, сложные условия стилей |
| Исключения | Таблицы не ограничены 12 пт; стили заголовков, титульника, TOC, подписей и кода отделяются от основного текста | Достаточная читаемость, законность конкретного исключения, согласованный размер |
| Поля и ссылки | Наличие PAGE/TOC, отсутствующие цели REF/PAGEREF, повторные закладки, SEQ в известных стилях подписей | Правильность объектов, порядок нумерации, свежесть кэша полей, соответствие оглавления пагинации |
| Таблицы | Прямая и указанная стилем заливка, доступные границы таблицы, цвета и различия толщин | Все границы ячеек, условные стили и их переопределения, повтор головки, продолжение, переносимые части |
| Текст | Предупреждения о длинном тире, двух нежелательных фразах, возможных заполнителях | Цитаты и технические строки, факты, источники, достоверность испытаний |

Скрипт распознаёт роли по стилям (включая имена стандартных стилей Word независимо от их технического ID), уровню заголовка и нахождению в таблице. При неизвестном пользовательском стиле результаты нужно сверять с назначением абзаца. Код отмечается стилем с `Code` или «Код» в имени. Служебную таблицу можно явно пометить `w:tblCaption w:val="cw:service"`; это исключает только её заливку и сетку, а не даёт права скрывать содержательную таблицу от проверки.

Свойства наследуются по docDefaults → цепочке basedOn → стилю абзаца → символьному стилю → прямому форматированию. Проверка не является полным движком Word: не вычисляет темы, номера списков, итоговый вид условных стилей таблиц, геометрию рисунков и позицию текста на странице. Источники и требования текущего пользователя имеют приоритет над автоматической классификацией.

## Обязательный завершающий цикл

1. Разобрать сообщения скрипта; исправить ошибки, вручную проверить предупреждения.
2. В доступном редакторе обновить SEQ/REF/PAGE/TOC, пересчитать страницы и снова обновить оглавление. Не считать один флаг updateFields доказательством пересчёта.
3. Отрендерить окончательный DOCX и осмотреть все страницы. После изменений повторить затронутые проверки и оглавление.
4. Сохранить редактируемый DOCX и при необходимости отдельные исходники диаграмм. Исходные методички не менять.
